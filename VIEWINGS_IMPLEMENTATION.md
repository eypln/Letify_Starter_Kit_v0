# Viewings Feature - Complete Implementation Guide

## Overview
Complete property viewing tracking system with calendar view, autocomplete, email notifications, and analytics integration.

## Database Schema

### Viewings Table
```sql
CREATE TABLE viewings (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id TEXT NOT NULL,
  ref_no TEXT,
  city TEXT,
  viewing_date DATE,
  viewing_time TIME,
  client_name TEXT,
  client_mobile_no TEXT,
  result TEXT CHECK (result IN ('DEAL', 'NO DEAL', 'Negotiating', 'Scheduled')),
  comments TEXT,
  inform_teamleader BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### RLS Policies
- **SELECT**: Users can only view their own viewings
- **INSERT**: Users can only create viewings for themselves
- **UPDATE**: Users can only update their own viewings
- **DELETE**: Users can only delete their own viewings

### Indexes
- `idx_viewings_created_at`: For sorting by creation date
- `idx_viewings_user_id`: For user-specific queries

## API Endpoints

### Main CRUD API
**File**: `app/api/viewings/route.ts`

- **GET**: Fetch user's viewings (paginated, 30/page)
- **POST**: Create new viewing + send email if inform_teamleader=true
- **PUT**: Update viewing + send email if inform_teamleader=true
- **DELETE**: Delete viewing

### Autocomplete APIs
**Files**:
- `app/api/viewings/listings-suggestions/route.ts`
- `app/api/viewings/clients-suggestions/route.ts`

- **Listings**: Returns listing_id, title (ref_no), city
- **Clients**: Returns id, name, phone

## UI Components

### Viewings Page
**File**: `app/dashboard/viewings/page.tsx`

#### Table View
- **Columns**: #, Created Date, Ref No, City, Viewing Date, Viewing Time, Client Name, Client Mobile No, Result, Comments, Inform Teamleader
- **Pagination**: 30 records per page
- **Click to Edit**: Row click opens edit modal

#### Add/Edit Modal
**Form Fields**:
1. **Ref No**: CreatableSelect (autocomplete from listings.title)
2. **City**: Auto-fills when ref_no selected
3. **Viewing Date**: DatePicker (dd.MM.yyyy)
4. **Viewing Time**: Select dropdown (07:00-21:00, 15-min intervals)
5. **Client Name**: CreatableSelect (autocomplete from clients.name)
6. **Client Mobile No**: Auto-fills when client selected
7. **Result**: Select (DEAL, NO DEAL, Negotiating, Scheduled)
8. **Comments**: Textarea
9. **Inform Teamleader**: Checkbox

**Validation**:
- All fields required except comments
- Custom English validation messages
- Hidden input hack for react-select required validation

#### Calendar View
- **Layout**: 3 months (previous, current, next)
- **Horizontal Scroll**: Swipe through months
- **Daily Cards**:
  - Viewing ID (#123)
  - Time (15:30)
  - Ref No
- **Color Coding**:
  - DEAL → bg-green-100
  - NO DEAL → bg-red-100
  - Negotiating → bg-blue-100
  - Scheduled → bg-yellow-100
- **Today Highlight**: Purple background
- **Click to Edit**: Card click opens modal

## Email Notifications

### Configuration
**File**: `.env.local`
```env
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=your-email@gmail.com
SMTP_PASS=your-app-password
```

### Email System
**File**: `lib/email.ts`

**Functions**:
- `sendEmail(to, subject, html)`: Send email via nodemailer
- `generateViewingNotificationEmail(viewing)`: Generate HTML template

**Recipients**: Users with `role='teamleader'` in profiles table

**Trigger**: When `inform_teamleader` checkbox is true during create/update

**Email Content**:
- Viewing details (date, time, ref_no, city)
- Client information (name, mobile)
- Property information
- Result status
- Comments

## Technical Notes

### Time Format Handling
- **Database**: TIME format (e.g., "19:00:00")
- **Display**: Use `.substring(0, 5)` to show "19:00"
- **Input**: Select dropdown with 96 options (7am-9pm, 15min intervals)

### Autocomplete Implementation
- **Library**: react-select / CreatableSelect
- **Auto-fill Logic**: onChange → find matching record → update dependent fields
- **Example**: 
  - Select ref_no → Auto-fill city from listing
  - Select client_name → Auto-fill phone from client

### Form Validation
- **React-Select Required**: Hidden input field with HTML5 validation
- **Custom Messages**: onInvalid/onInput handlers for English messages
- **Date Validation**: DatePicker component handles invalid dates

### Activity Logging
**When**: Every POST and PUT operation
**Data Logged**:
```json
{
  "type": "new_viewing_added" | "viewing_updated",
  "data": {
    "ref_no": "19756",
    "client_name": "John Doe"
  }
}
```

## Known Issues & Solutions

### Issue: TIME field shows seconds (19:00:00)
**Solution**: Use `.substring(0, 5)` for display

### Issue: React-Select doesn't support HTML5 required
**Solution**: Add hidden input field with required attribute

### Issue: Date picker format inconsistency
**Solution**: Use consistent dd.MM.yyyy format everywhere

### Issue: Email sending blocks API response
**Solution**: Email is async, doesn't block response
